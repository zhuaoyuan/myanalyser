# 宽存窄用与回测公平性 — 整体方案与分步实施路线

日期：2026-03-15

- `20260315_宽存窄用与回测公平性设计.md`

---

## 1. 总体目标与原则

**目标**  
在任意回测时点 T 上，使用完全“点时间”可用的数据，确保跨年份回测样本公平可比，并消除 look-ahead。

**核心原则：宽存窄用**  
数据准备阶段尽可能保留全量原始数据；回测阶段按每个 T 进行截取、筛选与加工。

**公平性口径**  
- 统一相对窗口：`[T - lookback, T]`  
- 统一未来验证窗口：`[T, T + hold_days]`  
- 严格点时间：仅使用 `<= T` 的数据

---

## 2. 关键问题与一致结论

| 问题 | 结论 | 影响 |
|---|---|---|
| Filter 无 `--end-date` | 属实 | 存在 look-ahead |
| Integrity 区间固定 | 属实 | 只能单次区间复用 |
| 静态参数导致不公平 | 属实 | 不同 T 实际窗口不同 |
| Prep 支持按 T 调用 | 属实 | 可直接复用 |
| Scoreboard 支持截断 | 属实 | 可按 T 使用 |

**一致建议**  
P0 必须引入 `filter_end_date`，并将 Integrity 拉大至最大跨度；其余为增强与扩展。

## 3. 整体性设计（目标态）

### 3.1 数据分层

| 层级 | 内容 | 目标 |
|---|---|---|
| L1 原始数据 | ETL 全量（NAV、分红、拆分、overview、cyrjg、gmbd、fee 等） | 宽存 |
| L2 全跨度明细 | Integrity / Compare 明细 | 复用 |
| L3 参数化中间 | Filter / Prep eligible / Scoreboard | 按 T 缓存 |
| L4 回测结果 | period_detail / report | 可选 |

### 3.2 回测点时间流程（单 T）

```
1) prep_eligible(T)     # 点时间 eligible
2) filter(T-lookback, T)  # 规则 4/5 仅判 [start, end]
3) eligible ∩ (purchase - filtered_out)
4) scoreboard(T)        # latest_nav_date = T
5) backtest(T, T+hold_days)
```

### 3.3 设计约束

- 所有使用的数据必须 **<= T**  
- Filter 与 Scoreboard 必须支持 **end-date/ latest-nav-date**  
- 交易日口径需统一（T 必须为交易日）

## 4. 关键流程重新定位与数据解耦（详细设计）

以下三处是“宽存窄用”的关键控制面：`prep_data_workflow.py`、`run_full_pipeline.sh`、`tools/pybroker_fund_backtest.py` 与 `src/backtest/*`。为避免影响既有流程，**重设计落地在独立目录 `myanalyser/src/v2` 与 `myanalyser/tools/v2`**。目标是将“全量获取”和“点时间使用”彻底解耦，避免时间口径混用。

### 4.1 `prep_data_workflow.py` 的职责重新划分（v2）

**现状问题**  
单脚本同时承担：拉取全量数据 + 点时间筛选 eligible，容易在 T 选择上产生隐性耦合。

**目标定位**  
- Fetch-only（宽存）：只负责全量数据获取与落盘，不依赖 `--date`  
- Eligible-only（窄用）：只读已缓存 CSV，按 `T` 做过滤，不触发任何网络或增量抓取

**建议拆分方式（保持兼容）**  
1. 保留 CLI，但新增 `--mode`（在 v2 脚本中实现）。  
`fetch`：只跑 step x/a/b/c/e，产出 L1。  
`eligible`：只跑 `_apply_filters(date=T)`。  
`full`：保持旧行为（默认）。  
2. 新增轻量入口供回测编排调用：  
`src/v2/transforms/prep_eligible_from_cached.py`，只接收 `work_dir` + `date`，禁止联网。

**关键输出契约**  
`work_dir` 内固定文件名：  
`fund_purchase.csv`、`fund_cyrjg.csv`、`fund_gmbd.csv`、`fund_fee_structured.csv`、`fund_overview.csv`  
`prep_eligible` 产出：`prep_result.csv`（不按 T 划分）
说明：该文件仅承担“过滤绝对不可能使用的数据、减轻后续流程工作量”的功能；在宽存背景下，条件应改为**不依赖 T 的全局硬过滤**。

### 4.2 `run_full_pipeline.sh` 的职责重新划分

**现状问题**  
脚本混合“数据准备 + 过滤 + 回测前置”，且过滤窗口由静态变量控制，易与回测 T 混淆。

**目标定位**  
作为 **L1+L2 产出编排器**（ETL + Integrity + Compare）。  
仅在需要单次验证时才引入 “点时间”逻辑（如 `AS_OF_DATE`）。

**建议调整**  
1. 明确 `AS_OF_DATE` 语义，仅用于单次验证/榜单。  
2. 若传 `AS_OF_DATE`，自动映射：  
`FILTER_END_DATE=AS_OF_DATE`  
`SCOREBOARD_LATEST_NAV_DATE=AS_OF_DATE`  
3. 多 T 回测完全移出该脚本，由 backtest runner 负责。

**输出契约**  
仅产出 L1：`data/versions/{run_id}/fund_etl/`  
说明：L2（integrity/compare）与单 T 输出（filter/scoreboard）在新分工下由独立流程负责，不再由 `run_full_pipeline.sh` 产出。

### 4.3 回测流程的职责重新划分（v2：`tools/v2/pybroker_fund_backtest.py` + `src/v2/backtest/*`）

**现状问题**  
回测入口与底层 loader 混用，容易绕过点时间限制或在入口处混用窗口口径。

**目标定位**  
提供明确的点时间回测入口，并将时间切片逻辑集中在 backtest 层。

**建议 API 形态**  
`tools/v2/pybroker_fund_backtest.py` 作为统一入口，内部只调用“点时间安全 API”。  
`run_point_in_time_backtest(run_id, as_of_date, lookback, hold_days, ...)`  
`load_point_in_time_data(run_id, as_of_date, lookback, ...)`  
`get_filter_chain(as_of_date=...)`

**实现原则**  
所有 load 函数必须有 `end_date` 或 `as_of_date`。  
数据层完成截断，不允许上层绕过。  
`src/v2/backtest/*` 仅暴露点时间安全的高层 API。

## 5. 分步实施方案（建议路线）

### Phase 0（P0，职责重定位与主干解耦）

**目标：把“宽存”和“窄用”在流程层面彻底分离**

1. **prep 分层改造（宽存，v2）**  
   - `tools/v2/prep_data_workflow.py` 增加 `--mode {fetch|eligible|full}`  
   - `fetch` 仅产出 L1 原始数据，不依赖 `--date`  
   - `eligible` 仅做“全局硬过滤”，输出 `prep_result.csv`（不按 T 划分）

2. **run_full_pipeline 只负责 L1（宽存）**  
   - 移除/停用 L2 与单 T 输出（integrity/compare/filter/scoreboard）  
   - `run_full_pipeline.sh` 仅做 ETL + 数据落盘

3. **回测入口收敛（窄用，v2）**  
   - `tools/v2/pybroker_fund_backtest.py` 作为唯一入口  
   - 只允许使用“点时间 API”，任何加载都要求 `as_of_date`

**验收要点**  
- run_full_pipeline 只产出 L1  
- prep_result.csv 不再依赖 `T`  
- 回测入口无绕过点时间的路径  

---

### Phase 1（P1，点时间能力补齐）

**目标：回测阶段实现严格点时间截断**

4. **Filter 增加 `--end-date`（v2 实现）**  
   - 规则 4、5 仅判定 `[start_date, end_date]`  
   - 回测调用时：`filter_end = T`

5. **Scoreboard / Backtest 统一 `as_of_date`（v2 实现）**  
   - 所有净值、人事、指标加载强制 `<= T`

6. **交易日口径统一**  
   - T 非交易日自动前移  
   - lookback 采用交易日或自然日统一口径（需文档固定）

**验收要点**  
- 任一 T 回测不会读取 T 之后数据  
- 回测结果在不同 T 之间可比  

---

### Phase 2（P2，效率与复用）

**目标：降低多 T 回测成本**

7. **L3 参数化缓存（filter/scoreboard，v2 实现）**  
   - 缓存键包含 `(run_id, start, end)` / `(run_id, latest_nav_date)`  
   - 增加 `ruleset_version`，避免规则变更污染

8. **多 T 滚动回测编排器**  
   - 输入 T 列表或 `[T_start, T_end, step]`  
   - 汇总年度对比、收益曲线、回撤等

**验收要点**  
- 多 T 回测重复计算显著下降  
- 缓存命中率可观  

---

### Phase 3（P3，可选优化）

9. **L2 明细按需计算（v2 独立工具）**  
   - integrity/compare 作为独立工具按需生成  
   - 仅当有质量排查需求时调用

10. **prep 入口进一步收敛（v2）**  
   - 抽取 `_apply_filters` 到独立模块  
   - 保证 fetch/eligible 共用同一过滤逻辑

## 6. 风险与缓解

| 风险 | 等级 | 缓解 |
|---|---|---|
| run_full_pipeline 仅产出 L1 导致下游依赖断裂 | 中 | 切换前梳理依赖清单，保留兼容开关或迁移脚本 |
| prep_eligible 变为全局硬过滤导致样本口径变化 | 中 | 明确硬过滤规则清单并版本化，做差异对比 |
| 回测入口收敛后仍可绕过点时间 | 高 | backtest 数据层强制 `as_of_date`，无参报错并加断言 |
| Filter 增加 `--end-date` 导致结果变化 | 中 | 记录差异并解释原因，更新回归基线 |
| 交易日对齐策略不一致 | 中 | 统一交易日历与对齐规则，写入文档与代码常量 |
| 缓存污染/过期 | 中 | 增加 `ruleset_version`，按 run_id 隔离并提供清理策略 |
| L2 改为按需生成导致质量检查缺失 | 低 | 设置定期健康检查或手动触发流程 |

## 8. 结论与建议

整体路线更新为（v2 并行演进）：  
- **P0**：职责重定位（prep 分层、pipeline 只产 L1、回测入口收敛）  
- **P1**：点时间能力补齐（end-date、as_of_date、交易日对齐）  
- **P2**：缓存与多 T 编排  
- **P3**：L2 质量工具按需化  

该路线先解决“流程层面的时间耦合”，再补齐严格点时间约束，最后做效率与质量工具化，符合宽存窄用的目标路径。
