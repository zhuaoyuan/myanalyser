## 四、阶段 A 实现路径（已选定 A3）

verify step10 当前从 ClickHouse 读选基 + 净值，新 backtest 仅支持本地 CSV。可选方案：

| 方案 | 说明 | 成本与维护 |
|------|------|------------|
| **A1：新 backtest 增加 ClickHouse 支持** | 在 backtest 或 data 模块增加 `load_from_clickhouse()`，供 step10 直接调用 | 原生支持，维护集中；开发量中等 |
| **A2：verify 导出 CSV 再喂新 backtest** | step10 先用已有逻辑从 ClickHouse 导出选基+净值 CSV，再调 pybroker_fund_backtest 消费 | 不改 backtest，仅改 verify 脚本；需约定 CSV 格式与路径 |
| **A3：适配层**（**已选用**） | 写薄适配脚本，从 ClickHouse 取数后转成 backtest 所需格式并调用 | 快速上线；长期存在维护成本，需评估与 A1 的投入对比 |

## 五、清理建议与顺序

### 可选前置：filter_one 解耦（建议先做）

在阶段 A 之前，先将 `filter_one` 抽成共享模块（如 `fund_metrics_core` 或新建 `most_stable_logic.py`），统一导入路径：

- 当前不一致：`most_stable_strategy` 用 `filter_score.filters.most_stable`（短路径），`test_backtest_pybroker_comprehensive` 用 `myanalyser.src.filter_score.filters.most_stable`（完整路径）
- 抽取后：两者均从共享模块导入，降低阶段 A/B 单次改动量

### 阶段 A：仅替换 backtest_portfolio（filter_score 保留）

1. **实现路径**：按「四、阶段 A 实现路径」选定方案落地（A1/A2/A3）。
2. **verify.sh**：step10 中用新 backtest 或适配层替换 `src/backtest_portfolio.py` 调用。
3. **测试迁移**：
   - `test_backtest_portfolio.py`：删除后，`_assign_selection_versions`、`_build_windows` 等逻辑需迁移到新 backtest 的对应单测，或若新 backtest 无等价能力则移除。
   - `test_cli_integration.test_backtest_cli_smoke_with_run_id_layout`：改为调用新 backtest 入口（或适配层），维持「CLI smoke + 产物存在检查」的覆盖；由 `test_cli_integration` 继续负责该 smoke。
4. **文档**：更新 `docs/系统设计.md`、`docs/README.md` 中 backtest 相关描述。
5. **删除**：`src/backtest_portfolio.py`。

### 阶段 B：逐步弱化或移除 filter_score

1. **解耦依赖**：将 `filter_score.filters.most_stable.filter_one` 抽成共享逻辑（若前置未做，此处补做），统一 `myanalyser.src.*` 导入路径。
2. 若 filter_score 流水线仍需要：保留 `run_filter_and_score.sh`、`filter_and_score_main.py` 及 test_filter_score，仅解除 backtest 对 filter_score 的导入。
3. 若计划完全移除 filter_score：需迁移/重写所有 filter 与 score 策略，并替换 step10b 的验收逻辑。
4. **temp_use 脚本处理**：
   - `diagnose_most_stable_007540.py`：完全移除 filter_score 时，**迁移**到从共享 `filter_one` 导入，或若无诊断需求则**删除**。
   - `verify_scored_result_metrics.py`：仅引用 `artifacts/filter_score_run_*` 路径，filter_score 移除后若 step10b 保留类似流水线则**保留**并更新路径；若 step10b 取消则**删除**。

## 六、回滚方案

- 替换前：将 `backtest_portfolio.py` 复制为 `backtest_portfolio.py.bak` 或打 tag，便于对比与回滚。
- 替换后若 verify 或单测失败：可临时恢复 step10 调用旧 `backtest_portfolio.py`，待问题修复后再切回新 backtest。
- 建议：旧脚本保留至少一个迭代周期（或至 `make verify` 连续通过 2 次以上）后再物理删除。
